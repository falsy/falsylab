<h3>1. Redux</h3>
<p class="basic-text-box">첫 번째로 가장 오래되고 여전히 가장 많은 사람들이 사용하는 Redux에 대해 알아봅니다.<br>일단, 간단한 구현 코드를 하나 만들어 볼까요?</p>
<pre class="legacy-code"><code class="language-ts">// /src/reducers/todos.ts
import { createSlice } from &quot;@reduxjs/toolkit&quot;

interface ITodo {
  id: number
  text: string
  completed: boolean
}

const todosSlice = createSlice({
  name: &quot;todos&quot;,
  initialState: [] as ITodo[],
  reducers: {
    todoAdded(state, action) {
      state.push({
        id: action.payload.id,
        text: action.payload.text,
        completed: false,
      })
    },
    todoToggled(state, action) {
      const todo = state.find((todo) =&gt; todo.id === action.payload)
      if (todo) {
        todo.completed = !todo.completed
      }
    },
  },
})

export const { todoAdded, todoToggled } = todosSlice.actions
export default todosSlice.reducer</code></pre>
<p class="basic-text-box">Redux 웹 사이트에 Redux Toolkit를 추천하면서 알려주는 예시 코드인데요. 오.. 예전 기억에 리듀서들 만들고 액션들 만들고 이것저것 할 게 많았던 거 같은데, Redux Toolkit를 사용하면 아주 간단하게 구성할 수 있네요.</p>
<pre class="legacy-code"><code class="language-ts">// /src/components/Todo.tsx
import { useDispatch, useSelector } from &quot;react-redux&quot;
import { todoAdded, todoToggled } from &quot;../reducers/todos&quot;

export default function Todo() {
  const todos = useSelector((state: any) =&gt; state.todos)
  const dispatch = useDispatch()

  const addTodo = () =&gt; {
    dispatch(todoAdded({ id: todos.length + 1, text: &quot;New Todo&quot; }))
  }

  const toggleTodo = (id: number) =&gt; {
    dispatch(todoToggled(id))
  }

  return (
    &lt;div&gt;
      &lt;button onClick={addTodo}&gt;Add Todo&lt;/button&gt;
      {todos.map((todo: any) =&gt; (
        &lt;div key={todo.id} onClick={() =&gt; toggleTodo(todo.id)}&gt;
          {todo.text} {todo.completed.toString()}
        &lt;/div&gt;
      ))}
    &lt;/div&gt;
  )
}</code></pre>
<h3>2. Flux Architecture</h3>
<p class="left-line-box">기습 Flux 아키텍처</p>
<p class="basic-text-box">React를 이야기하다 보면 자주 이야기되는 Flux 아키텍처입니다. 혹시나 그로 인해 React가 사용하는 아키텍처라고 생각할 수도 있는데, Flux는 React의 전역 상태 관리에 대한 체계적인 방법이 필요 했고 그렇게 개발한 아키텍처가 Flux 아키텍처입니다.<br>그리고 Flux의 아이디어를 기반으로 만들어진 라이브러리 중 하나가 Redux랍니다.</p>
<p class="left-line-box">React에 대한 자세한 이야기는 다음 포스트에서..</p>
<figure><img style="max-width: 100%;" src="/wp-content/uploads/2024/09/flux.png" alt=""></figure><p></p>
<p class="basic-text-box">Flux 아키텍처는 기본적으로 React와 같이 단방향 데이터 흐름을 가지며 크게, Action, Dispatcher, Store, View 로 역할을 나누고 각 역할을 아래와 같습니다.</p>
<p class="basic-text-box">- 액션(Action): 애플리케이션에서 발생하는 모든 이벤트를 의미합니다.<br>- 디스패처(Dispatcher): 액션을 스토어로 전달하는 역할을 합니다.<br>- 스토어(Store): 애플리케이션의 상태를 관리하고, 상태 변경이 발생하면 뷰에 알려줍니다.<br>- 뷰(View): React 컴포넌트로 구성되며, 스토어로부터 상태를 받아 UI를 업데이트합니다.</p>
<p class="basic-text-box">간단하게 요약하면 (이미 요약되어 있지만..) View는 우리가 아는 그 맨날 만드는 React 컴포넌트들을 이야기하고, Store는 전역 상태 값들을 관리하는 곳으로 상태값이 변경되면 그 변경을 View에 알려주고 View는 그럼 컴포넌트를 갱신하겠죠? Dispatcher는 이제 액션을 스토어에 전달하는 허브 역할을 하고 Action은 Type 값을 통해서 스토어에 상태값을 변경하는 함수를 이야기 한답니다.</p>
<p class="left-line-box">다시 Redux로 돌아가서..</p>
<h3>3. 다시 Redux</h3>
<p class="basic-text-box">Flux도 알아 봤으니, Redux는 Flux의 아이디어를 구체화한 라이브러리이고 특징에 대해 조금 더 알아보자면,</p>
<p class="basic-text-box">첫 번째로 단일 스토어 구성. Flux는 여러개의 Store를 사용할 수 있도록 하고 각 Store 간의 직접적인 통신은 없고 서로 독립적으로 동작하는 구성인데 반해, Redux는 전체 상태를 하나의 Store를 사용함으로써 상태의 일관성을 유지하고 디버깅에 용이하게 하였답니다.</p>
<p class="basic-text-box">두 번째로, Redux는 상태가 불변 객체로 관리되어 상태를 직접 변경하지 않고 Reducer를 통해서 새로운 상태 객체를 반환합니다.</p>
<p class="left-line-box">이 부분은 조금 의외였어요. 당연히 Flux 아키텍처에서도 store의 상태를 기본적으로 불변 객체로 관리하는 것으로 설계했을 줄 알았는데, Flux는 store의 상태 값의 불변성 여부를 유연하게 열어 놓았더라고요.</p>
<p class="left-line-box">좀 더 생각해보니까, React의 useState도 일반적으로 새로운 객체를 생성해서 사용하는거지 불변성을 강제하지는 않았네요?! 이게 약간 페이스북의 어떤 철학? 정책? 인가봐요.</p>
<p class="basic-text-box">세 번째로, Redux는 미들웨어 두어서 추가적으로 비동기 작업이나 로깅 등 추가 기능을 확장할 수 있게 구성하였습니다. 아무래도 Redux는 오랜시간 많은 사람들이 사용하였기에 이 미들웨어 풀도 넓어서 큰 장점일 수 있는 거 같아요.</p>
<p class="basic-text-box">위에 'Redux Toolkit' 예시는 action이나 reducer의 type 값이 안보이는데, 예전에 Redux 사용할 때는 아래의 예시처럼 type을 사용했었답니다. 아마도 내부적으로 type 값을 자동으로 만들어서 사용하겠죠??</p>
<pre class="legacy-code"><code class="language-ts">import { createStore } from &#x27;redux&#x27;

// Reducer
function counter(state = 0, action) {
  switch (action.type) {
    case &#x27;INCREMENT&#x27;:
      return state + 1
    case &#x27;DECREMENT&#x27;:
      return state - 1
    default:
      return state
  }
}

// Dispatch + Action
store.dispatch({ type: &#x27;INCREMENT&#x27; })</code></pre>
<p class="left-line-box">위와 같이 Redux는 Reducer를 사용해서 상태 값의 불변성을 보장합니다.</p>
<p class="basic-text-box">마지막으로 Redux의 DevTools를 통한 디버깅의 장점도 살짝 알아보자면,</p>
<pre class="legacy-code"><code class="language-bash">  $ npm install redux-devtools-extension</code></pre>
<p class="basic-text-box">라이브러리를 설치해주고</p>
<pre class="legacy-code"><code class="language-ts">// /webpack.config.js

<p class="basic-text-box">개발 모드인지 확인하기 위한 Webpack 설정 파일에 DefinePlugin을 통해 환경 변수를 추가해주고</p>

<h3>4. Recoil</h3>
<p class="basic-text-box">Recoil는 페이스북이 만든 전역 상태 관리 라이브러리로 React의 상태 관리 모델에 맞춘 원자(atom) 단위의 상태 관리 라이브러리 입니다. 조금전에 만든 todo를 간단하게 Recoil로 구현해보면,</p>

<pre class="legacy-code"><code class="language-ts">// /src/hooks/useTodo.ts
import { atom, useRecoilState } from &quot;recoil&quot;

interface ITodo {
  id: number
  text: string
  completed: boolean
}

const todoState = atom({
  key: &quot;todoState&quot;,
  default: [] as ITodo[],
})

export const useTodoState = () =&gt; {
  return useRecoilState(todoState)
}</code></pre>
<pre class="legacy-code"><code class="language-ts">// /src/components/Todo.tsx
import { useTodoState } from &quot;../hooks/useTodo&quot;

export default function Todo() {
  const [todos, setTodos] = useTodoState()

  const addTodo = () =&gt; {
    setTodos((currVal) =&gt; {
      return [
        ...currVal,
        { id: todos.length + 1, text: &quot;New Todo&quot;, completed: false },
      ]
    })
  }

  const toggleTodo = (id: number) =&gt; {
    setTodos((currVal) =&gt; {
      return currVal.map((todo) =&gt; {
        if (todo.id === id) {
          return { ...todo, completed: !todo.completed }
        }
        return todo
      })
    })
  }

  return (
    &lt;div&gt;
      &lt;button onClick={addTodo}&gt;Add Todo&lt;/button&gt;
      {todos.map((todo: any) =&gt; (
        &lt;div key={todo.id} onClick={() =&gt; toggleTodo(todo.id)}&gt;
          {todo.text} {todo.completed.toString()}
        &lt;/div&gt;
      ))}
    &lt;/div&gt;
  )
}</code></pre>
<p class="basic-text-box">짜잔 어떤가요? 간단하죠?</p>

<p class="basic-text-box">이처럼 페이스북에서 직접 개발하고, 쉽고, 간단한 구성이 Recoil의 장점인 거 같아요. 하지만 시간이 지나면서 점점 사용하는 비중이 줄고 있는데요. 일단 가장 큰 문제는 1년 넘게 업데이트가 없습니다.. 그동안 발견된 메모리 누수 이슈나 이제는 아주 일반적으로 사용되는 SSR에서의 지원도 부족한 상황에 업데이트까지 멈춰서 이제는 많은 개발자들이 떠나고 있습니다.</p>
<p class="left-line-box">만약 지금 시작하는 프로젝트라면, Recoil을 사용하지는 않을 거 같아요.</p>
<h3>5. Zustand</h3>
<p class="basic-text-box">Zustand는 현시점에서 가장 부상하고 있는?(아마도?) 전역 상태 관리 라이브러리랍니다.<br>현재 npm의 주간 다운로드를 보면, '@reduxjs/toolkit'은 약 370만 다운로드를 기록하고 있으며 'zustand'는 약 430만 다운로드를 기록하고 있답니다.</p>
<p class="left-line-box">그런데 'react-redux'가 주간 다운로드가 약 790만 다운로드인 것으로 보아, 그래도 여전히 가장 많이 사용되는 상태 관리 라이브러리는 Redux인 거 같아요.</p>
<p class="basic-text-box">Zustand는 Recoil 보다도 적은 코드량으로 간단하게 구성할 수 있으며 다른 라이브러리들과 달리 React의 Context API를 사용하지 않고 클로저로 사용해서 별도의 Provider 감싸주지 않아도 된답니다.</p>
<p class="basic-text-box">여기서 잠시 코드를 보면,</p>
<pre class="legacy-code"><code class="language-ts">// /src/hooks/useTodo.ts
import { create } from &quot;zustand&quot;

interface ITodo {
  id: number
  text: string
  completed: boolean
}

type Todos = {
  list: ITodo[]
  todoAdded: () =&gt; void
  todoToggled: (id: number) =&gt; void
}

const useStore = create()((set) =&gt; ({
  list: [],
  todoAdded: () =&gt;
    set((Todos) =&gt; ({
      list: [
        ...Todos.list,
        { id: Todos.list.length + 1, text: &quot;New Todo&quot;, completed: false },
      ],
    })),
  todoToggled: (id: number) =&gt;
    set((Todos) =&gt; ({
      list: Todos.list.map((todo) =&gt;
        todo.id === id ? { ...todo, completed: !todo.completed } : todo
      ),
    })),
}))

export default useStore</code></pre>
<pre class="legacy-code"><code class="language-ts">// /src/components/Todo.tsx
import useTodo from &quot;../hooks/useTodo&quot;

export default function Todo() {
  const { list, todoAdded, todoToggled } = useTodo()

  const addTodo = () =&gt; {
    todoAdded()
  }

  const toggleTodo = (id: number) =&gt; {
    todoToggled(id)
  }

  return (
    &lt;div&gt;
      &lt;button onClick={addTodo}&gt;Add Todo&lt;/button&gt;
      {list.map((todo: any) =&gt; (
        &lt;div key={todo.id} onClick={() =&gt; toggleTodo(todo.id)}&gt;
          {todo.text} {todo.completed.toString()}
        &lt;/div&gt;
      ))}
    &lt;/div&gt;
  )
}</code></pre>
<p class="basic-text-box">와우! 엄청 간단하죠?!<br>제가 개인 프로젝트로 전역 상태 관리가 필요하다면 전 고민 없이 Zustand를 사용할 거 같아요.<br>조금 더 Zustand의 특징을 살펴보자면,</p>
<p class="basic-text-box">앞서 이야기한대로 Zustand는 React의 Context API를 사용하지 않고 클로저를 통한 상태 저장과 구독 시스템을 사용하기 때문에 React의 컴포넌트 트리와 독립적으로 전역 상태를 관리할 수 있습니다.</p>
<p class="basic-text-box">이 말을 조금 쉬운 상황으로 설명하자면, Context API를 사용하는 Provider가 있고 해당 Context의 값이 변경되면 Provider 안의 컴포넌트들이 불필요하게 리렌더링 될 수 있는데, Zustand는 Context API를 사용하지 않기 때문에 해당 상태값이 연결된 컴포넌트에만 리렌더링이 발생한다는 의미입니다.</p>
<p class="left-line-box">혹시, Context API를 사용하는 Redux나 Recoil은 Zustand에 비해 리렌더링이 많이 발생하는 비효율적인 라이브러리인가?! 라고 생각할 수 있는데, Redux나 Recoil 모두 해당 상태를 구독하고 있는 컴포넌트를 추적하고 실제로 선택된 값이 변경되는지 확인 후 리렌더링 하도록 최적화되어 있어서 그렇지 않습니다.<br />(위와 같은 최적화에도 작은 오버헤드가 있을 수 있으니, 그마저도 없다 정도로 이해하면 될 것 같습니다.)</p>
<p class="basic-text-box">너무 Zustand의 장점만 말한 것 같아서, Redux에 비교했을 때 단점을 조금 정리해보면,</p>
<p class="basic-text-box">Zustand는 매우 간결하게 상태를 관리할 수 있지만, Redux는 actions, reducers, middlewares등 상태 변경에 대한 흐름이 명확히 구조화 되어 있어서 규모가 커졌을 때 상태 관리가 어려울 수 있습니다.</p>
<p class="left-line-box">하지만 이 부분은 뭐.. 규모가 커졌을때는 흐름에 대한 상태를 구조화 하는 건 너무 당연한 거라, 오히려 서비스에 맞게 또는 조직에 맞게 자유롭게 구성할 수 있으니 막 단점이라 생각되지는 않는 거 같아요.</p>
<p class="basic-text-box">Redux에는 다양한 미들웨어들이 있다?!</p>
<p class="left-line-box">저는 Redux를 사용할 때 미들웨어를 많이 사용하지는 않아서 자세히는 잘 모르겠어요.<br>(Redux에 비해 규모는 작지만, Zustand도 미들웨어를 지원한답니다.)</p>
<p class="basic-text-box">Redux는 중앙 집중식의 단일 스토어를 사용하기 때문에 디버깅이나 상태 추적에 용이합니다. 그리고 Redux DevTools도 잘 만들어저 있어서 이 부분이 Redux에게 굉장히 매력적인 부분인 거 같아요.</p>
<p class="left-line-box">(Zustand도 DevTools가 있습니다.)</p>

<h3>6. Context API</h3>
<p class="basic-text-box">React는 v16.3부터 Context API를 사용할 수 있는데요, Context API를 사용하면 해당 Provider 안에서 간단하게 전역의 상태를 관리할 수 있습니다.</p>
<p class="basic-text-box">하지만 주의할 점은, 앞서 이야기 나왔던 것처럼 Context API는 상태값이 변경됨에 따라 Provider 아래의 모든 컴포넌트가 리렌더링 될 수 있기 때문에 React.Memo나 useMemo, useCallback를 사용해서 렌더링 최적화를 직접 구현해줘야 합니다.</p>
<p class="highlight_color2" style="margin-top: 15px; margin-bottom: 10px; padding-left: 2px;">2024.10.10 내용추가</p>
<p class="left-line-box">React v18 기준으로 Context API도 렌더링의 최적화가 진행되어 Provider 아래의 컴포넌트 중에 Context를 구독하는 컴포넌트만 리렌더링 됩니다.</p>
<p class="basic-text-box">그리고 당연히 별도의 미들웨어도 없고, 복잡한 상태의 변경 흐름을 관리하고 조합하는데 어려운 단점이 있습니다. 이어지는 이야기지만 디버깅이 어렵다는 문제도 있습니다.</p>
<p class="basic-text-box">하지만 전역 상태 라이브러리들은 대부분 애플리케이션 전체의 상태를 관리하는데 초점을 두고 있기 때문에 특정 기능이 국소적으로 사용되는 형태라면 Context API도 괜찮은 선택지가 될 수 있습니다.</p>
<p class="basic-text-box">예를 들자면,</p>
