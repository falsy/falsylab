<h3>1. React v16</h3>

<p class="basic-text-box">
  16 버전부터 시작합니다!
</p>

<h3>1-1. React v16.0</h3>
<p class="basic-text-box">
  리액트 16.0 버전의 변경사항은 크게 fragments, errorBoundary, portals, custom DOM 속성 지원과 파일 크기 및 server-side 렌더링 개선입니다.
  <a href="https://legacy.reactjs.org/blog/2017/09/26/react-v16.0.html" target="_blank" rel="noopener noreferrer">https://legacy.reactjs.org/blog/2017/09/26/react-v16.0.html</a>
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[fragments]</span>
  그"&lt;Fragment&gt; ... &lt;/Fragment&gt;" 또는  "&lt;&gt; ... &lt;/&gt;" 이걸 이야기하는 건 아니고 아래와 같이 배열 요소를 렌더에 응답 값으로 사용할 수 있습니다.
</p>

<pre class="legacy-code"><code class="language-ts">render() {
  // No need to wrap list items in an extra element!
  return [
    // Don&#x27;t forget the keys :)
    &lt;li key=&quot;A&quot;&gt;First item&lt;/li&gt;,
    &lt;li key=&quot;B&quot;&gt;Second item&lt;/li&gt;,
    &lt;li key=&quot;C&quot;&gt;Third item&lt;/li&gt;,
  ];
}</code></pre>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[errorBoundary]</span>
  이전까지는 컴포넌트에서 오류가 발생하면 전체 애플리케이션이 중단되었는데, 이제 새롭게 추가된 "componentDidCatch(error, info)" 또는 "static getDerivedStateFromError()" (또는 둘 모두의) 라이프사이클 메서드를 사용해서 이름 그대로 오류의 경계를 만들 수 있습니다.
  <a href="https://ko.legacy.reactjs.org/docs/error-boundaries.html" target="_blank" rel="noopener noreferrer">https://ko.legacy.reactjs.org/docs/error-boundaries.html</a>
</p>

<pre class="legacy-code"><code class="language-ts">class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }

  static getDerivedStateFromError(error) {
    // 다음 렌더링에서 폴백 UI가 보이도록 상태를 업데이트 합니다.
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    // 에러 리포팅 서비스에 에러를 기록할 수도 있습니다.
    logErrorToMyService(error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      // 폴백 UI를 커스텀하여 렌더링할 수 있습니다.
      return &lt;h1&gt;Something went wrong.&lt;/h1&gt;;
    }

    return this.props.children;
  }
}</code></pre>

<pre class="legacy-code"><code class="language-ts">  &lt;ErrorBoundary&gt;
    &lt;MyWidget /&gt;
  &lt;/ErrorBoundary&gt;</code></pre>

<p class="left-line-box">
  알아둘 점은, 자식 요소에서의 에러만을 감지하고, 서버 사이드 렌더링, 이벤트 핸들러, 비동기적 코드(예: setTimeout 혹은 requestAnimationFram)는 감하지 않습니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[Portals]</span>
  Portal은 부모 컴포넌트의 DOM 계층 구조 밖의 노드로 자식을 렌더링합니다.
</p>

<pre class="legacy-code"><code class="language-ts">&lt;!DOCTYPE html&gt;
&lt;html lang=&quot;ko&quot;&gt;
  &lt;head&gt;
    &lt;meta charset=&quot;UTF-8&quot; /&gt;
    &lt;meta name=&quot;viewport&quot; content=&quot;width=device-width, initial-scale=1.0&quot; /&gt;
    &lt;title&gt;React&lt;/title&gt;
  &lt;/head&gt;
  &lt;body&gt;
    &lt;div id=&quot;root&quot;&gt;&lt;/div&gt;
    &lt;div id=&quot;modal-root&quot;&gt;&lt;/div&gt;
  &lt;/body&gt;
&lt;/html&gt;</code></pre>

<p class="basic-text-box">
  이렇게 id 값이 "modal-root" 라는 엘리먼트를 만들어 놓고
</p>

<pre class="legacy-code"><code class="language-ts">import { ReactNode, useState } from &quot;react&quot;
import ReactDOM from &quot;react-dom&quot;

const Modal = ({ children }: { children: ReactNode }) =&gt; {
  return ReactDOM.createPortal(
    &lt;div className=&quot;modal&quot;&gt;{children}&lt;/div&gt;,
    document.getElementById(&quot;modal-root&quot;) as HTMLElement
  )
}

export default function Portal() {
  const [isModalOpen, setModalOpen] = useState(false)

  const toggleModal = () =&gt; {
    setModalOpen(!isModalOpen)
  }

  return (
    &lt;div&gt;
      &lt;h1&gt;React Portals&lt;/h1&gt;
      &lt;button onClick={toggleModal}&gt;
        {isModalOpen ? &quot;Close Modal&quot; : &quot;Open Modal&quot;}
      &lt;/button&gt;

      {isModalOpen &amp;&amp; (
        &lt;Modal&gt;
          &lt;div&gt;
            &lt;h2&gt;Modal&lt;/h2&gt;
            &lt;button onClick={toggleModal}&gt;Close&lt;/button&gt;
          &lt;/div&gt;
        &lt;/Modal&gt;
      )}
    &lt;/div&gt;
  )
}</code></pre>

<p class="basic-text-box">
  이렇게 하면, Modal 컴포넌트는 "modal-root" 엘리먼트의 자식 요소로 생성된답니다.
</p>

<pre class="legacy-code"><code class="language-ts">  ...
  &lt;body&gt;
    &lt;div id=&quot;root&quot;&gt;
      ...
    &lt;/div&gt;
    &lt;div id=&quot;modal-root&quot;&gt;
      &lt;div class=&quot;modal&quot;&gt;
        &lt;div&gt;
          &lt;h2&gt;Modal&lt;/h2&gt;
          &lt;button&gt;Close&lt;/button&gt;
        &lt;/div&gt;
      &lt;/div&gt;
    &lt;/div&gt;
  &lt;/body&gt;
&lt;/html&gt;</code></pre>

<p class="left-line-box">
  생각보다.. 글이 길어지고 있어서.. 이제는 더 간단하게..
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[custom DOM]</span>
  custom DOM은 이전 버전에는 비표준 HTML 속성을 모두 제거했는데 v16부터는 클라이언트와 서버 렌더러가 모든 비표준 속성을 허용한다는 이야기입니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[파일 크기 개선]</span>
  그 다음 파일 크기 개선은 말 그대로 파일의 크기가 30% 정도 줄었다고 해요.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[SSR(Server-Side Rendering) 개선]</span>
  마지막으로 SSR(Server-Side Rendering) 개선은 이전까지는 render 메서드를 사용했었는데, v16부터는 hydrate 메서드가 추가되었습니다. 만약 React를 서버 사이드에서 사용한다면
</p>

<pre class="legacy-code"><code class="language-ts">import { render } from &quot;react-dom&quot;
import MyPage from &quot;./MyPage&quot;
render(&lt;MyPage/&gt;, document.getElementById(&quot;content&quot;));</code></pre>

<p class="left-line-box">
  v16 이전까지 위와 같이 선언했다면,
</p>

<pre class="legacy-code"><code class="language-ts">import { hydrate } from &quot;react-dom&quot;
import MyPage from &quot;./MyPage&quot;
hydrate(&lt;MyPage/&gt;, document.getElementById(&quot;content&quot;));</code></pre>

<p class="left-line-box">
  v16 이후는 위와 같이 선언
</p>

<p class="basic-text-box">
  서버 사이드 렌더링을 사용할 때, hydrate를 사용한다면, hydrate는 SSR로 이미 생성된 HTML을 받아서 그것과 연관된 React 컴포넌트를 연결(Mount)하는 작업을 수행합니다. 여기서 React는 이미 서버에서 생성된 HTML과 비교하면서 필요한 부분만 업데이트하고 이벤트 바인딩을 설정합니다.
</p>

<p class="basic-text-box">
  이로써 서버에서 생선한 HTML을 재사용하기에 초기 로딩 속도가 빨라지고 이후 클라이언트에서 생성한 React 컴포넌트의 가상 DOM과 비교하여 필요한 부분만 리렌더링하기에 효율적으로 DOM을 업데이트 한답니다!
</p>

<pre class="legacy-code"><code class="language-ts">import React from &quot;react&quot;

const LazyComponent: React.FC = () =&gt; {

import Portal from &quot;./Portal&quot;

const LazyComponent = lazy(() =&gt; import(&quot;./LazyComponent&quot;))

export default function App() {

    &lt;div&gt;

      &lt;section&gt;
        &lt;h2&gt;Lazy&lt;/h2&gt;
        &lt;button onClick={() =&gt; setLoad(true)}&gt;Load&lt;/button&gt;
        {load &amp;&amp; (

<h3>2. React v17</h3>

<p class="basic-text-box">
  17 버전은 새로운 기능 도입 없이 내부 동작의 개선이나 안정성, 호환성을 개선하는 업데이트를 하였습니다.
</p>


<h3>2-1. React v17.0.0</h3>

<p class="basic-text-box">
  - 점진적 업그레이드
  - 이벤트 시스템 개선
  - 새로운 JSX 트랜스폼 지원
  - 일부 라이프사이클 메서드 제거
</p>

<p class="basic-text-box">
  점진적 업그레이드가 가능하게 변경이 되었는데요. 이게 무슨말이냐면 이전까지는 새로운 React 버전이 릴리스되고 새로운 버전으로 업데이트를 하면 애플리케이션의 전체 코드를 업데이트 된 버전의 코드로 변경해 줘야했었는데 v17 부터는 부분적으로, 점진적으로 마이그레이션이 가능하게 되었습니다.
</p>

<p class="basic-text-box">
  이전까지 이벤트가 Document에 위임했었는데 v17 부터는 React의 Root로 DOM 컨테이너에 이벤트를 연결합니다. 이전까지 Document에서 모든 이벤트를 제어하게 되면 외부의 라이브러리나 여러 Root를 사용할 때 문제가 발생할 여지가 있습니다. 그리고 Documnet라는 하나의 리스너에 모든 이벤트를 처리하는 것은 비표준적이기 때문에 Root DOM 컨테이너를 사용하는 것이 일반적인 브라우저 이벤트 처리 방식과 유사하게 동작합니다.
</p>

<p class="basic-text-box">
  새로운 JSX 트랜스폼 지원으로 "import React from 'react'" 구문을 사용하지 않아도 새로운 JSX 트랜스폼에 의해 자동으로 JSX를 변환하는 코드를 추가합니다.
</p>

<p class="basic-text-box">
  componentWillMount, componentWillReceiveProps, componentWillUpdate 메서드가 제거되었습니다. 이는 렌더링이 취소되거나 중단될 때 의도하지 않은 부작용을 일으킬 수 있어서 제거되었습니다. 
  componentWillMount 대신 componentDidMount를 사용하여 컴포넌트아 마운트 된 후에 호출되도록 하고, componentWillReceiveProps 대신 getDerivedStateFromProps를 사용하여 새로운 props를 받아서 안전하게 업데이트하며 componentWillUpdate 대신 getSnapshotBeforeUpdate를 사용하여 DOM이 업데이트 되기전 스냅샷을 찍어 업데이트 후 이를 참조하도록 합니다.
</p>


<h3>2-2. React v17.0.1, v17.0.2</h3>

<p class="basic-text-box">
  v17.0.1, v17.0.2 에서는 대체로 버그 수정과 호환성 개선, 그리고 React DevTools 개선이 있었습니다.
</p>

<h3>3. React v18</h3>

<p class="basic-text-box">
  마지막으로 글 작성 시점의 최신 버전인 v18 에 대해서 알아봅니다.
</p>

<h3>3-1. React v18.0</h3>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[createRoot]</span>
  이전의 render()를 사용하지 않고 createRoot를 사용하여야 v18에 추가된 새로운 동작을 수행합니다.
</p>

<pre class="legacy-code"><code class="language-ts">// v17
import ReactDOM from &quot;react-dom&quot;
import App from &quot;./App&quot;

ReactDOM.render(&lt;App /&gt;, document.getElementById(&quot;root&quot;))</code></pre>

<pre class="legacy-code"><code class="language-ts">// v18
import { createRoot } from &quot;react-dom/client&quot;
import App from &quot;./App&quot;

const container = document.getElementById(&quot;root&quot;)
const root = createRoot(container)
root.render(&lt;App /&gt;)</code></pre>

<p class="left-line-box">
기존의 render 메서드를 사용하던 방식이 createRoot로 변경된 것처럼, v16에서 SSR 개선을 위해 추가된 hydrate 메서드 역시 hydrateRoot로 지원합니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[Automatic Batching]</span>
  다음으로 "Automatic Batching" 기능이 추가되었습니다.
  아래의 예를 보면,
</p>

<pre class="legacy-code"><code class="language-ts">import { useState } from &quot;react&quot;

export default function Batching() {
  const [state1, setState1] = useState(0)
  const [state2, setState2] = useState(false)

  const onClick = () =&gt; {
    setState1((prev) =&gt; prev + 1)
    setState2((prev) =&gt; !prev)
  }

  console.log(&quot;render&quot;)

  return (
    &lt;&gt;
      &lt;div&gt;{state1}&lt;/div&gt;
      &lt;div&gt;{state2.toString()}&lt;/div&gt;
      &lt;button onClick={onClick}&gt;button&lt;/button&gt;
    &lt;/&gt;
  )
}</code></pre>

<p class="basic-text-box">
  위와 같이 클릭시 setState가 2번 일어나지만, 해당 컴포넌트의 렌더링은 1번 발생해서 "render"라는 로그는 1번만 출력된답니다. 이걸 일괄 처리(Batching)라고 하는데요.
</p>

<p class="basic-text-box">
  사실, 위 일괄 처리(Batching)는 v18 이전에서도 동작하던 내용이고 새롭게 추가된 내용은 아래와 같습니다.
</p>

<pre class="legacy-code"><code class="language-ts">import { useState } from &quot;react&quot;

export default function Batching2() {
  const [state1, setState1] = useState(0)
  const [state2, setState2] = useState(false)

  const onClick = () =&gt; {
    setTimeout(() =&gt; {
      setState1((prev) =&gt; prev + 1)
      setState2((prev) =&gt; !prev)
    }, 500)
  }

  console.log(&quot;render&quot;)

  return (
    &lt;&gt;
      &lt;div&gt;{state1}&lt;/div&gt;
      &lt;div&gt;{state2.toString()}&lt;/div&gt;
      &lt;button onClick={onClick}&gt;button&lt;/button&gt;
    &lt;/&gt;
  )
}</code></pre>

<p class="basic-text-box">
  v18 이전까지는 Promise, 네이티브 이벤트 핸들러, setTimeout 또는 기타 이벤트 내부의 업데이트는 기본적으로 일괄 처리 되지 않았지만 v18 부터는 자동으로 일괄 처리됩니다.
</p>

<p class="basic-text-box">
  간단히 이야기하면 기존의 일괄 처리(Batching)가 콜스택 범위까지만 동작을 했고 v18 부터는 태스트 큐까지 동작하도록 업데이트 되었습니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[startTransition, useTransition]</span>
  다음으로 "startTransition" 및 "useTransition" 훅이 추가되었는데요.
  참고: <a href="https://react.dev/reference/react/useTransition" target="_blank" rel="noopener noreferrer">https://react.dev/reference/react/useTransition</a>
</p>

<p class="basic-text-box">
  아래의 예시 코드를 먼저 살펴보면,
</p>

<pre class="legacy-code"><code class="language-ts">import { useState } from &quot;react&quot;
import PostsTab from &quot;./SlowPost&quot;

export default function TransitionState() {
  const [menu, setMenu] = useState(&quot;A&quot;)

  const handleClick = (name: string) =&gt; {
    setMenu(name)
  }

  return (
    &lt;div style={{ maxHeight: &quot;200px&quot;, overflow: &quot;hidden&quot; }}&gt;
      &lt;button
        onClick={() =&gt; handleClick(&quot;A&quot;)}
        style={{ color: menu === &quot;A&quot; ? &quot;red&quot; : &quot;black&quot; }}
      &gt;
        A
      &lt;/button&gt;
      &lt;button
        onClick={() =&gt; handleClick(&quot;B&quot;)}
        style={{ color: menu === &quot;B&quot; ? &quot;red&quot; : &quot;black&quot; }}
      &gt;
        B
      &lt;/button&gt;
      &lt;button
        onClick={() =&gt; handleClick(&quot;C&quot;)}
        style={{ color: menu === &quot;C&quot; ? &quot;red&quot; : &quot;black&quot; }}
      &gt;
        C
      &lt;/button&gt;
      &lt;div style={{ padding: &quot;5px 10px&quot;, background: &quot;#f5f5f5&quot; }}&gt;

        {menu === &quot;B&quot; &amp;&amp; &lt;PostsTab /&gt;}
        {menu === &quot;C&quot; &amp;&amp; &lt;p&gt;C&lt;/p&gt;}
      &lt;/div&gt;
    &lt;/div&gt;
  )

<p class="basic-text-box">
  위 샘플 코드에서 "PostsTab" 컴포넌트가 렌더링 하는데 굉장히 느린 컴포넌트이고 이때 "A", "B", "C"를 연달아 클릭하면 B가 렌더링 하는 동안 UI가 멈추고 C가 뒤늦게 활성화되는 것을 확인할 수 있습니다.
</p>

<pre class="legacy-code"><code class="language-ts">import { useState, useTransition } from &quot;react&quot;

      setMenu(name)
    })
  }

  return (
    &lt;div style={{ maxHeight: &quot;200px&quot;, overflow: &quot;hidden&quot; }}&gt;

        B

      &lt;button

<p class="basic-text-box">
  하지만 위와 같이 useTransition 훅을 사용하고 마찬가지로 "A", "B", "C"를 연달아 클릭한다면, "B"의 렌더링과 상관없이 바로 마지막 선택한 "C"가 활성화되는 것을 확인할 수 있습니다.
</p>

<p class="basic-text-box">
  이와 같이 useTransition는 UI를 차단하지 않고 상태를 업데이트 할 수 있는 훅입니다. 그리고 사용하지 않은 _ 인자는 "isPending" 플래그로 대기중인 Transition이 있는지 알려줍니다. 예를 들면, isPending 플래그를 사용해서 Loading 뷰를 보여줄 수 있습니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[userId]</span>
  이어서 계속 추가된 훅을 알아보겠습니다. 다음은 "userId" 입니다.
  참고: <a href="https://react.dev/reference/react/useId" target="_blank" rel="noopener noreferrer">https://react.dev/reference/react/useId</a>
</p>

<pre class="legacy-code"><code class="language-ts">&lt;label&gt;
  Password:
  &lt;input
    type=&quot;password&quot;
    aria-describedby=&quot;password-hint&quot;
  /&gt;
&lt;/label&gt;
&lt;p id=&quot;password-hint&quot;&gt;
  The password should contain at least 18 characters
&lt;/p&gt;</code></pre>

<p class="basic-text-box">
  React 에서는 컴포넌트는 반복적으로 사용될 수 있기 때문에 ID를 직접 입력하는 것을 추천하지 않습니다.
</p>

<pre class="legacy-code"><code class="language-ts">import { useId } from &#x27;react&#x27;

function PasswordField() {
  const passwordHintId = useId()
  return (
    &lt;&gt;
      &lt;label&gt;
        Password:
        &lt;input
          type=&quot;password&quot;
          aria-describedby={passwordHintId}
        /&gt;
      &lt;/label&gt;
      &lt;p id={passwordHintId}&gt;
        The password should contain at least 18 characters
      &lt;/p&gt;
    &lt;/&gt;
  )
}</code></pre>

<p class="basic-text-box">
  위와 같이 "useId" 훅을 사용하면 화면에 여러 번 나타나도 ID가 출돌하지 않습니다.
</p>

<p class="left-line-box">
  리스트에서 key 값으로 "useId"를 사용하지 않습니다. 리스트에서 key는 데이터에서 생성합니다.
</p>

<p class="basic-text-box">
  그밖의 추가된 훅은 아래와 같습니다.
</p>

<p class="basic-text-box">
  - useDeferredValue : 급하지 않은 리렌더링을 지연시킬 수 있습니다.
  - useSyncExternalStore (라이브러리에서 사용) : React 컴포넌트가 외부 스토어(상태 관리 라이브러리, 브라우저 API로 관리되는 상태)의 상태를 동기적으로 읽고 구독할 수 있습니다.
  - useInsertionEffect (라이브러리에서 사용) : CSS-in-JS 라이브러리가 렌더링에서 스타일을 삽입할 때 발생하는 성능 문제를 해결할 수 있는 새로운 훅입니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[Strict Mode]</span>
</p>

<p class="basic-text-box">
  v18에서는 StrictMode가 더욱 강화되어, 개발 모드에서의 디버깅과 검사에 도움을 주는 추가적인 동작이 포함되었습니다. 그리고 렌더링에 필요한 시간, 리소스 로딩 시점 등을 더 자세히 분석할 수 있도록 돕습니다.
</p>

<p class="left-line-box">
  이 과정에서 컴포넌트가 처음 마운트될 때마다 자동으로 언마운트 및 리마운트하고 두 번째 마운트 시 이전 상태를 복원하는 새로운 개발 전용 검사를 도입합니다.
</p>

<p class="basic-text-box">
  <span style="font-size: 18px; display: inline-block; margin-bottom: 5px;">[Suspense]</span>
</p>

<p class="basic-text-box">
  v16.6에 추가된 Suspense가 v18에서 여러 개선과 기능이 추가되며 정식 기능이 되었습니다.
</p>

<p class="basic-text-box">
  v17까지 Suspense는 클라이언트 사이드 렌더링(CSR)에서만 사용되었지만, v18에서는 서버 사이드 렌더링(SSR)에서도 Suspense를 사용할 수 있게 되었습니다.
</p>

<p class="basic-text-box">
  이제 Suspense가 서버 스트리밍을 지원하여, 서버에서 Suspense 경계 안의 컴포넌트가 서스펜드되면 React는 해당 경계의 fallback 내용을 보내고, 이후 비동기 작업이 완료되면 클라이언트에서 트리를 다시 렌더링하여 보여줍니다. 이렇게 하여 초기 로딩을 더 빠르게 할 수 있습니다.
</p>
