<p class="basic-text-box">오늘은 지난 주말에 저의 반나절의 시간을 빼앗아간 문제에 대해 적어 보려 합니다.
사실 리액트 네이티브를 제대로 사용해 본 적이 없어서, 사실 엄청 간단한 건데 저만 고생한 걸 굳이 글로 쓰고 있는 건 아닌지 조금 걱정이 되긴 하지만... 빼앗긴 시간이 너무 아까운 나머지 보상 심리로..
짧게 적어보려 합니다.</p>

<h3>1. 글을 쓰기 앞서</h3>
<p class="basic-text-box">
          반나절을 빼앗겼다고 적었지만 사실.. 해결은 아래 링크의 글을 통해 한방에 해결하였답니다.
링크. <a href="https://medium.com/@dushyant_db/how-to-import-files-from-outside-of-root-directory-with-react-native-metro-bundler-18207a348427" target="_blank" rel="noopener noreferrer">https://medium.com/@dushyant_db/how-to-import-files-from-outside-of-root-directory-with-react-native-metro-bundler-18207a348427</a></p>
<p class="basic-text-box">
          그리고 제가 작성한 예시는 그냥 'npx react-native init projectName' 하면 생성되는 파일 그대로입니다.
그래도 혹시 전체 코드를 확인이 필요하시다면 아래의 깃허브 리포지토리에서 확인하실 수 있습니다.
링크. <a href="https://github.com/falsy/blog-post-example/tree/master/react-native-import" target="_blank" rel="noopener noreferrer">https://github.com/falsy/blog-post-example/tree/master/react-native-import</a></p>

<h3>2. 문제의 상황</h3>
<p class="basic-text-box">
          저는 리액트 네이티브 프로젝트 디렉토리 밖의 js 파일을 임포트 해야 하는 일이 있었는데, 리액트 네이티브 프로젝트 디렉토리에서 상대 경로로 루트 디렉토리 밖의 파일을 임포트하면 아래와 같이 모듈을 찾지 못하는 문제가 생긴답니다.</p>
<p class="basic-text-box">
        	저는 외부에 external 이라는 폴더를 만들고 그 안에 test.js 파일을 만들고 그 안에 내용은 아래와 같습니다.</p>

<pre class="legacy-code"><code class="language-javascript">// ../external/test.js
export default { test: &#x27;test&#x27; };</code></pre>
<p class="basic-text-box">
        	그리고 리액트 네이티브의 시작인 index.js 파일에 아래와 같이 코드를 추가하였습니다.</p>

<pre class="legacy-code"><code class="language-javascript">// index.js
import {AppRegistry} from &#x27;react-native&#x27;;
import App from &#x27;./App&#x27;;
import {name as appName} from &#x27;./app.json&#x27;;
import test from &#x27;../external/test&#x27;;

console.log(test);
AppRegistry.registerComponent(appName, () =&gt; App);</code></pre>
<p class="basic-text-box">
					문제의 화면은 아래와 같습니다.</p>

<h3>3. 해결</h3>
<p class="basic-text-box">
          react-native init을 하면 metro.config.js 파일이 있는데요. 바로 요놈을 아래와 같이 수정하면 된답니다.</p>

<pre class="legacy-code"><code class="language-javascript">// metro.config.js
const path = require(&#x27;path&#x27;);
const watchFolders = [
  path.resolve(__dirname + &#x27;/../external&#x27;),
];

module.exports = {
  transformer: {
    getTransformOptions: async () =&gt; ({
      transform: {
        experimentalImportSupport: false,
        inlineRequires: false,
      },
    }),
  },
  watchFolders,
};</code></pre>
<p class="basic-text-box">
          보통 이런 내용 다음에는 metro가 무엇인지 설명해야 하지만, 그것은 이 글의 논지가 아니므로!
간단하게 리액트 네이티브에서 사용하는 자바스크립트 번들러랍니다.</p>
<p class="left-line-box">
          사실, metro는 지하철 말고는 잘 모릅니다.</p>
<p class="basic-text-box">
          대충 속성명으로 딱 추측이 가능하듯, 왓치할 폴더를 추가해주면 아래와 같이 문제가 해결된답니다.</p>

<figure><img style="max-width: 100%;" src="/wp-content/uploads/2020/12/2.jpg" alt=""></figure>
<h3>4. 이어지는 다음 문제</h3>
<p class="basic-text-box">
          그런데 만약에 저 외부의 파일에서 내부의 모듈을 사용하려고 하면 또 아래와 같은 문제가 생긴답니다.
예를 들어 test.js 파일에 React를 임포트 하면,</p>

<pre class="legacy-code"><code class="language-javascript">// ../external/test.js
import React from &#x27;react&#x27;;

export default { test: &#x27;test&#x27; };</code></pre>
<p class="basic-text-box">
					아래와 같은 오류가 출력된답니다.</p>

<figure><img style="max-width: 100%;" src="/wp-content/uploads/2020/12/3.jpg" alt=""></figure>
<h3>5. 이어지는 해결</h3>
<p class="basic-text-box">
					다시 metro.config.js 파일을 아래와 같이 수정합니다.</p>

<pre class="legacy-code"><code class="language-javascript">// metro.config.js
const path = require(&#x27;path&#x27;);
const extraNodeModules = {
  &#x27;external&#x27;: path.resolve(__dirname + &#x27;/../external&#x27;),
};
const watchFolders = [
  path.resolve(__dirname + &#x27;/../external&#x27;),
];

module.exports = {
  transformer: {
    getTransformOptions: async () =&gt; ({
      transform: {
        experimentalImportSupport: false,
        inlineRequires: false,
      },
    }),
  },
  resolver: {
    extraNodeModules: new Proxy(extraNodeModules, {
      get: (target, name) =&gt;
        name in target
          ? target[name]
          : path.join(process.cwd(), `node_modules/${name}`),
    }),
  },
  watchFolders,
};</code></pre>
<p class="left-line-box">
          와우, 잘 모르는데 설명하는 글을 적으려니 이런 곤욕이 없군요...</p>
<p class="basic-text-box">
        	역시 잘 모르지만 속성명으로 추측하면, metro는 자바스크립트의 번들러고 resolver 속성은 번들러가 번들을 진행될 때 참조가 되는 속성일 거에요. 그리고 extraNodeModules속성은 이름 그대로 노드 모듈을 추가 해주는 역할을 하겠네요.</p>
<p class="basic-text-box">
        	그전에 extraNodeModules 라는, 이후에 Proxy 객체의 타겟으로 사용될 대상을 지정해주었어요.
Proxy 객체는 ES6에 추가된 객체인데요. Proxy 객체를 설명하는 건 너무 어려운 일이니까.
우리의 MDN 형, 누나가 알려줄 거에요.
링크. <a href="https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Proxy" target="_blank" rel="noopener noreferrer">https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Proxy</a></p>
<p class="basic-text-box">
        	그러면 우리가 지정한 타겟(../external)에게 'process.cwd()' 절대 경로에 있는 node_modules디렉토리에서 모듈을 찾아서 연결해주나봐요.</p>
<p class="basic-text-box">
        	말도 안 되는 설명글이었지만...
위와 같이 설정을 해주면 아래와 같이 React를 임포트에도 오류가 출력되지 않는답니다.</p>
